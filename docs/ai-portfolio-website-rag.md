## 1. 项目一句话概述

这个个人网站是一个从 0 搭建的 AI 个人作品集网站，全程主要由 AI 协助完成。它不仅用于展示个人经历和项目，也作为作品集的一部分，展示作者对 AI 产品、AI 交互、知识库构建、Prompt 设计、前端实现和部署上线的完整实践。

## 2. 项目定位

这个网站不是传统静态作品集，而是一个带有 AI 分身能力的个人作品集网站。

网站的核心目标包括：

- 展示个人项目、工作经历和能力结构。
- 通过 AI 分身回答访问者关于作者经历、项目和能力的问题。
- 体现作者对 AI 时代设计师作品集形态的思考。
- 展示作者从产品设计视角参与完整产品生命周期的能力。

## 3. AI 分身是什么

AI 分身是基于 Dify 搭建的 AI 应用，并通过 API 接入到个人作品集网站中。

用户在网站中提问后，问题会被发送给 Dify 应用。Dify 会结合知识库内容和模型能力生成回答，并返回给网站前端展示。

AI 分身的作用不是替代真人，而是帮助访问者更高效地了解作者的经历、项目、技能和表达方式。

## 4. AI 分身的知识来源

为了降低模型猜测和幻觉，AI 分身使用了两类知识材料。

第一类是结构化后的真实简历资料，包括：

- 个人资料。
- 工作经历。
- 项目经验。
- 技能信息。

第二类是人格资料，用于让 AI 在表达方式上更接近作者本人，而不只是机械地回答问题。

人格资料的来源是微信聊天记录。原始聊天数据没有直接用于公开展示，而是先经过清洗、去噪、标签标注和人格特征提炼，最终整理成人格文档，再接入 Dify 知识库。

## 5. 微信聊天记录如何处理成人格资料

微信聊天记录被用于提炼作者的表达风格和人格特征。

处理流程包括：

1. 收集原始微信聊天记录。
2. 使用 Codex 按规则进行数据清洗。
3. 去除噪声、无关内容和不适合进入知识库的信息。
4. 对文本进行标签标注。
5. 提炼人格特征、表达习惯和沟通风格。
6. 整理成人格文档。
7. 将处理后的人格文档接入 Dify 知识库。

这个流程的目标是让 AI 分身在表达风格上更接近作者本人，同时避免直接暴露原始私聊内容。

## 6. RAG 在项目中的作用

该项目在 Dify 中使用 RAG，也就是检索增强生成。

用户提问后，系统会先从简历知识库和人格知识库中召回相关内容，再交给模型生成回答。

RAG 的作用包括：

- 让回答优先基于真实资料。
- 减少模型凭空猜测。
- 让 AI 能围绕作者的真实经历、项目和风格进行回答。
- 在知识覆盖范围内提升回答准确性和一致性。

## 7. Dify 中的知识库处理

在 Dify 中，简历资料和人格资料会进行分段处理。

分段处理的目的是让系统在用户提问时能够更准确地召回相关片段，而不是一次性把整份材料交给模型。

知识库主要包含两类内容：

- 简历知识库：用于回答关于个人资料、工作经历、项目经历、技能和行业经验的问题。
- 人格知识库：用于辅助 AI 学习作者的表达方式、沟通风格和语气特点。

## 8. 当前 AI 分身存在的问题

实际测试中发现，AI 分身仍然可能出现幻觉。

主要原因包括：

- 样本量有限。
- 知识库覆盖不完整。
- 部分问题边界模糊。
- 分段方式仍有优化空间。
- 召回策略仍需要继续调整。
- Prompt 对回答边界的约束还需要进一步强化。

这些问题说明，接入 RAG 并不等于完全消除幻觉。知识库质量、资料覆盖度、分段方式、召回策略和 Prompt 约束都会影响最终回答效果。

## 9. AI 分身后续优化方向

后续优化方向包括：

- 持续补充高质量语料。
- 优化知识库分段方式。
- 调整 Dify 的召回策略。
- 在 Prompt 中明确要求模型优先基于知识库回答。
- 当知识库无法确认答案时，要求模型直接说明“不确定”。
- 继续测试边界模糊问题，减少模型过度推断。

优化目标是让 AI 分身更可靠、更克制，并且更符合真实个人经历。

## 10. 网站搭建技术方案

网站采用 Figma、Codex、Dify 和 Vercel 组合完成搭建。

主要工具分工如下：

| 工具 | 作用 |
| --- | --- |
| Figma | 页面设计和视觉方案 |
| Codex | 前端代码生成、功能实现和调试 |
| ChatGPT | 方案设计、Prompt 编写和问题排查 |
| Dify | AI 应用、知识库和 RAG 能力 |
| GitHub | 代码管理 |
| Vercel | 自动部署和上线发布 |

## 11. 网站开发流程

网站开发流程大致如下：

1. 在 Figma 中完成页面设计。
2. 使用 Codex 协助完成前端页面开发。
3. 使用 Codex 实现网站功能和调试问题。
4. 使用 ChatGPT 进行方案设计、Prompt 编写和问题排查。
5. 将 Dify 应用通过 API 接入个人作品集网站。
6. 通过 GitHub 管理代码版本。
7. 部署到 Vercel，实现自动发布上线。

这个流程体现了 AI 参与产品开发的完整链路，而不只是单点辅助。

## 12. ChatGPT 和 Codex 在项目中的分工

ChatGPT 主要用于：

- 方案设计。
- 产品思路整理。
- Prompt 编写。
- 问题排查。
- 辅助分析 AI 分身的回答效果。

Codex 主要用于：

两者共同参与了从想法到实现的过程。

## 13. 项目的核心思考

这个项目本身并不复杂，但它承载了作者对“AI 时代设计师的作品集应该是什么样的”这一问题的思考。

传统作品集通常侧重于静态展示项目结果，而这个网站尝试让作品集本身变成一个可交互的 AI 产品。

它不仅展示作品，也展示作者如何理解 AI 产品、如何构建知识库、如何设计 Prompt、如何处理 AI 交互体验、如何完成前端实现，以及如何把产品发布上线。

## 18. 推荐回答边界

回答关于该项目的问题时，应优先基于本知识库内容。

如果知识库中没有明确答案，应直接说明“不确定”或“目前资料中没有提到”，不要自行补充不存在的细节。

对于原始微信聊天记录、私人对话、敏感个人信息等内容，应避免披露。可以说明人格资料来自经过清洗和提炼后的聊天记录摘要，但不应展示原始聊天内容。
